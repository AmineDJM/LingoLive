# Data safety form (Google Play)

Answers matching what the code does. **[depends]** marks an answer that changes
with deployment configuration and must be re-checked before each submission.

## Data collection and security

| Question                                                 | Answer                                                                                |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Does your app collect or share any required user data?   | Yes                                                                                   |
| Is all user data encrypted in transit?                   | Yes — TLS everywhere; transcripts are additionally encrypted at rest with AES-256-GCM |
| Do you provide a way for users to request data deletion? | Yes — in-app: Settings → Delete my data, and a documented URL                         |
| Has your data collection been independently verified?    | No — do not claim otherwise without an actual audit                                   |

## Data types

### Personal info

| Type          | Collected | Shared | Optional | Purpose            |
| ------------- | --------- | ------ | -------- | ------------------ |
| Email address | Yes       | No     | Yes      | Account management |
| User IDs      | Yes       | No     | No       | App functionality  |

The user ID is generated by the app for itself. It is not an advertising ID.
E-mail exists only for users who choose to create an account; the default
experience is a guest with no account.

### Audio

| Type                      | Collected | Shared | Optional | Purpose |
| ------------------------- | --------- | ------ | -------- | ------- |
| Voice or sound recordings | **No**    | —      | —        | —       |

Google's definition of "collected" is transmitted off the device. Audio _is_
transmitted for transcription and is processed transiently, so declare it as
**processed ephemerally**: Play's form has this exact option, and using it is
the honest answer. It is never recorded and never stored.

### Messages / other user content

| Type                         | Collected | Shared | Optional | Purpose           |
| ---------------------------- | --------- | ------ | -------- | ----------------- |
| Other user-generated content | Yes       | No     | Yes      | App functionality |

A transcript, and only when the user explicitly saves one. Unsaved transcripts
are deleted by a scheduled job within an hour.

### App activity

| Type             | Collected     | Shared | Optional | Purpose   |
| ---------------- | ------------- | ------ | -------- | --------- |
| App interactions | **[depends]** | No     | Yes      | Analytics |

Off by default. If enabled, the event catalogue is a closed list that cannot
carry conversation content.

### Crash and performance

| Type        | Collected     | Shared | Optional | Purpose           |
| ----------- | ------------- | ------ | -------- | ----------------- |
| Crash logs  | **[depends]** | No     | Yes      | App functionality |
| Diagnostics | **[depends]** | No     | Yes      | App functionality |

Only if an error-reporting DSN is configured.

### Not collected

Location, financial info, health and fitness, contacts, calendar, photos and
videos, files and documents, web browsing history, installed apps, device or
other IDs (advertising).

## Third parties

Speech and text are sent to our server, which relays them to OpenAI for
transcription and translation. This is a processor relationship, not sharing
for the processor's own purposes, and it is disclosed in the privacy policy.

The provider API key exists only on our server. It is not in the app, not in
the JavaScript bundle, not in any `EXPO_PUBLIC_*` variable — enforced by a lint
rule, a CI scan of the built bundle and a scan of the git history.

## Permissions declared

| Permission     | Why                                      | Optional                          |
| -------------- | ---------------------------------------- | --------------------------------- |
| `RECORD_AUDIO` | Transcribing speech while a session runs | No — the core function            |
| `CAMERA`       | Scanning a session QR code               | Yes — a code can be typed instead |

Explicitly blocked in the manifest: external storage, location (fine and
coarse) and contacts.

## Families / content

- Target audience: 13+ (not designed for children; do not opt into the
  Designed for Families programme)
- The app displays user-generated speech as text, so answer the UGC questions
  in the content rating questionnaire honestly
